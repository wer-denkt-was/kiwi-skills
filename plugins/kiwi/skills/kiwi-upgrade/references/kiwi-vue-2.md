# Upgrading frontends from Kiwi-Vue 1.x to 2.0

Kiwi-Vue 2 is the client library for Kiwi-Server 1.5, and Kiwi-Vue 1.x the one for Kiwi-Server 1.4: a 1.x client
can't update entities on a 1.5 server (`PUT` was removed), and a 2.0 client can't update them on a 1.4 server. The
frontend upgrade therefore belongs to the server upgrade, and both must be deployed together.

The source of truth is the section "Migrating from 1.x" of `../../kiwi-vue/references/CHANGELOG.md` (the Kiwi-Vue
changelog); `../../kiwi-vue/references/README.md` documents the 2.0 API. This file adds the concrete rewrites.

## Steps

1. **Dependency**: `"@werdenktwas/kiwi-vue": "^2.0.0"` in `package.json`, then `npm install` (or the project's
   package manager) to update the lock file. If there's no network, change `package.json` only and tell the user to
   update the lock file.
2. **Generated model**: if the frontend uses a `*.model.ts` generated by Kiwi-Server's `FieldsetSourceGeneratorTool`,
   regenerate it from the upgraded server (phase 5 must be done): the `ICreate…`/`IUpdate…` interfaces now contain
   exactly the body properties declared by the 1.5 generic commands, with their JSON keys. If the server isn't in this
   repository, ask the user for the regenerated file, or note it as open issue.
3. **CRUD services**: add the create and update body types as class type parameters, and remove the method type
   parameters of the body.
4. **Request bodies**: send only the properties the command declares, with its JSON keys (see below).
5. **Custom requests**: paths are relative to the API URL; `FetchApi` constructor changed.
6. **Error messages**: add the new codes, check conditional message keys.
7. **Removed/changed API**: `Ordinal`, `CredentialsInvalid.details`, `UsernamePassword.userDetails`.
8. Type check and test (`vue-tsc --noEmit` or `npm run build`, `npm test`), and fix what the compiler finds: most
   rewrites below are found by the type checker once the generated model and services are updated.

## Rewrites

| Kiwi-Vue 1.x                                                       | Kiwi-Vue 2.0                                                                             |
|--------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| `basicCrudService<ITodoItemDefault, TodoItemId>('TodoItem')`        | `basicCrudService<ITodoItemDefault, TodoItemId, ICreateTodoItem, IUpdateTodoItem>('TodoItem')` |
| `service.create<ICreateTodoItem, R>(body)`                         | `service.create<R>(body)` (body type from the class)                                     |
| `service.update<IUpdateTodoItem, R>(id, body)` (`PUT`, full body)  | `service.update<R>(id, body)` (`PATCH`, changed properties only)                          |
| `implements CrudService<T, ID>`                                    | `implements CrudService<T, ID, C, U>`                                                    |
| `api.request('/path', params, init)` to a path outside the API URL | `api.request(new URL('/path', baseUrl), init)`; paths are always relative to the API URL |
| `jsonRequest(path, body, 'PUT' \| 'POST')`                          | `jsonRequest(path, body, method, params?, init?)`, also `PATCH`/`DELETE`                  |
| `new FetchApi(baseUrl, preprocessor)`                              | `createApi({ apiUrl, credentials, fetch? })`, or `new FetchApi(baseUrl, fetch?, preprocessor?)` |
| `credentialsInvalid.details.credentials`                           | `credentialsInvalid.credentials`                                                         |
| `usernamePassword.userDetails`                                     | Removed (was always `null`)                                                              |
| `const enum Ordinal` (`Ordinal.LT`, …)                             | Unchanged usage; `Ordinal` is a constant object now, so `isolatedModules` works          |
| Catching `SyntaxError` for empty/non-JSON error responses          | `ApiError` with code `http-error` (by status) or `response-not-json`                     |

### Request bodies and JSON keys

Kiwi-Server 1.5 rejects unknown properties with `400 entity-body-invalid`, so typical 1.x patterns fail at runtime:

- **Updates with the whole entity**: `update(id, { ...item, title })` sends `id` and every field. Send only the
  changed properties: `update(id, { title })`. If a form edits several fields, collect the changed ones into an
  `IUpdate…` object.
- **Renamed keys**: generic `reference(…)` properties use the relation's schema field name as key, e.g. `list` instead
  of `listId`. Take the keys from the regenerated `ICreate…`/`IUpdate…` interfaces, and from the "Client-facing
  changes" of `KIWI-UPGRADE.md` if the server was upgraded in this branch.
- **`null` values**: a JSON `null` is only accepted for nullable properties; 1.4 handlers often ignored it. Don't send
  `null` for fields the user didn't change.
- **Absent keys**: in updates, absent keys are left unchanged; nothing has to be sent to keep a value.

### Error messages

- Add messages for `entity-body-invalid`, or for its nested codes (`entity-field-missing-value`,
  `entity-field-invalid`, `entity-field-unknown`, `entity-mismatched-input`); without a message for
  `entity-body-invalid`, the messages of the nested errors are shown, one per line. Conditions can target a field:
  `entity-field-missing-value[fieldName=title]`.
- `403` responses use the code of the response body if present (e.g. `access-denied`, or a `DomainException` code):
  add messages for these codes besides `forbidden`.
- `401` responses reject with `UnauthorizedError` (code `unauthorized`); add a message, and check where the
  application handled 401 before (e.g. redirect to login on a generic error).
- `resourceErrorTransformer`: a condition on an absent detail no longer matches (it matched in 1.x).
- Conditions in message keys are separated by `,` (`&` still works).

## Checklist per frontend

- [ ] `package.json` on `^2.0.0`, lock file updated (or noted as open issue)
- [ ] Generated model regenerated from the 1.5 server (or noted as open issue)
- [ ] Every `basicCrudService`/`CrudService` has four type parameters; no `create<…, …>`/`update<…, …>` left
- [ ] Update calls send changed properties only; no `id`, no keys the command doesn't declare
- [ ] Custom `api.request`/`jsonRequest` paths checked; no leading-slash path that was meant to leave the API URL
- [ ] Error messages for `entity-body-invalid` (or its nested codes), `access-denied`, `unauthorized`
- [ ] Type check and tests pass; client-facing changes listed in `KIWI-UPGRADE.md`
