# 9. Troubleshooting - Kiwi Server

This chapter is intended to help with known problems, pitfalls and issues.

If you don't find the solution to your problem here, please amend this document once the issue is solved to document
how to resolve it.

## Application startup

### Database migrations are not run

The application fails to start, because Hibernate's schema validation does not find the tables of your entities or
of the Kiwi modules, although the Liquibase changelogs exist:

```
Caused by: org.hibernate.tool.schema.spi.SchemaManagementException: Schema validation: missing table [todo_list]
```

Spring Boot 4 moved the Liquibase auto-configuration into its own module. With only `org.liquibase:liquibase-core` on
the classpath, the migrations are silently skipped. To resolve this, make sure that:

1. The build script declares `org.springframework.boot:spring-boot-starter-liquibase` instead of `liquibase-core`
2. The master changelog is located at `src/main/resources/db/changelog/db.changelog-master.yaml`, or configured in
   `spring.liquibase.change-log`
3. The master changelog includes the changelogs of the Kiwi modules your application uses, i.e.
   `classpath:db/changelog/db.storage-master.xml` and `classpath:db/changelog/db.audit-log-master.xml`
   (see [Chapter 1: "Database migrations"](./01-introduction.md#database-migrations))

### "Not a managed type" for application entities

The application fails to start, because a Spring Data repository refers to an entity that is not part of the JPA
persistence unit:

```
Caused by: java.lang.IllegalArgumentException: Not a managed type: class com.example.domain.TodoList
```

Spring Boot scans the package of your `@SpringBootApplication` class and its sub-packages for entities. The Kiwi
modules register their own entity packages in addition to these. If you declare `@EntityScan`, only the packages
given by `@EntityScan` are scanned for your entities, again in addition to the Kiwi module entities.

To resolve this, make sure that:

1. Your entity classes are located in the package of the application class or one of its sub-packages, or
2. An `@EntityScan` annotation (`org.springframework.boot.persistence.autoconfigure.EntityScan`) on a configuration
   class lists all packages containing your entity classes. If your repositories are located outside the application
   package as well, they also need an `@EnableJpaRepositories` annotation listing their packages.

> Note: Kiwi 1.4 and earlier required a bare `@EntityScan` and `@EnableJpaRepositories` on the application class,
> together with `@Import`s of the Kiwi configuration classes. Since Kiwi 1.5, the Kiwi modules are configured by
> Spring Boot auto-configuration, and these annotations can be removed.

### NullPointerException from static JPA metamodel attributes

You may encounter a `NullPointerException` when a query filter or analytical report refers to the static JPA
metamodel, e.g. `TodoItem_.class_!!` or `TodoItem_.status`. The root cause of the stacktrace may look similar to this:

```
Caused by: java.lang.NullPointerException
	at com.example.domain.TodoItemReportQuery.getRoot(TodoQueries.kt:23) ~[main/:na]
```

The static metamodel fields are only initialized when the JPA persistence unit is started, and only for entity
classes that are included in the persistence unit. Until then, or if the entity is not part of the persistence unit,
they are `null`.

Example metamodel class generated by the Hibernate processor:

```java

@StaticMetamodel(TodoItem.class)
@Generated("org.hibernate.processor.HibernateProcessor")
public abstract class TodoItem_ extends de.kiwi.api.domain.BaseEntity_ {

    public static final String TODO_LIST = "todoList";
    public static final String TITLE = "title";
    public static final String STATUS = "status";

    // (!) These static volatile meta-attributes have not been initialized, so they are `null`
    public static volatile EntityType<TodoItem> class_;
    public static volatile SingularAttribute<TodoItem, TodoList> todoList;
    public static volatile SingularAttribute<TodoItem, String> title;
    public static volatile SingularAttribute<TodoItem, TodoItemStatus> status;
}
```

To resolve this, make sure that:

1. The entity class is included in the persistence unit, see
   ["Not a managed type" for application entities](#not-a-managed-type-for-application-entities)
2. Metamodel attributes are not read before the persistence unit has been initialized, e.g. in the initializer of a
   Kotlin `object` or a top-level property. Read them lazily instead, for example using a property getter like
   `override val root get() = TodoItem_.class_!!`

### Missing storage provider

The application fails to start with the following message:

```
Invalid value 'null' for configuration property 'kiwi.storage.provider'. Validation failed for the following reason:

The storage provider is required, configure one of: none (discards all file data), data-uri, s3, local; or declare a FileStorageService bean
```

The storage module is on the classpath, but neither is `kiwi.storage.provider` configured, nor does the application
declare its own `FileStorageService` bean. The provider has no default, so that files are never discarded unnoticed.
To resolve this, configure the provider, also in tests that start the storage auto-configuration. See [Chapter 5: "File Storage"](./05-infrastructure-integration.md#file-storage).

### Missing secret key for the local file storage

The application fails to start with one of the following messages:

```
java.lang.IllegalStateException: Missing kiwi.storage.local.token.secret-key
java.lang.IllegalArgumentException: Local file token secret key must have at least 256 bits
```

The `local` storage provider signs the URIs of stored files, and requires a Base64-encoded secret key of at least 256
bits in `kiwi.storage.local.token.secret-key`. To resolve this, generate a key, e.g. using
`head -c 32 /dev/random | base64`, and configure it. All application instances serving the same local file storage
must use the same key. See [Chapter 5: "File Storage"](./05-infrastructure-integration.md#file-storage).

Similarly, if the application fails to start with `Missing kiwi.storage.s3.access-key`, the storage module is
configured with the provider `s3`, which requires S3 credentials. Configure them, or the provider you want to use
instead, e.g. `local`.

### Duplicate generic commands for an entity type

The application fails to start with a message like this:

```
java.lang.IllegalStateException: Duplicate generic create command classes found for entity types:
com.example.domain.TodoList -> com.example.domain.CreateTodoList, com.example.domain.NewTodoList
```

Each entity type can have only one generic create, update and delete command class, and one generic query class.
This includes command classes marked by the annotations `@CreateCommand`, `@UpdateCommand` and `@DeleteCommand`.
Before Kiwi 1.5, one of the classes silently replaced the other, depending on the classpath scan order.
To resolve this, remove or rename the duplicate class, or turn it into a regular, non-generic command.
See [Chapter 3: "Generic Commands and Queries"](./03-application-command-query.md#generic-commands-and-queries).

## Web requests

### Requests with a trailing slash return 404

Since Kiwi 1.5 (Spring Framework 7), request paths with a trailing slash no longer match the mapping without it:
`GET /TodoList/` is not handled by the endpoint mapped to `/TodoList`, and results in a `404 Not Found` response.
This applies to the Kiwi generic endpoints and to your own controllers.

To resolve this, call the endpoints without the trailing slash. If clients that you can't change depend on trailing
slashes, you can register Spring's `UrlHandlerFilter` as a bean in your application, which strips the trailing
slash before the request is mapped:

```kotlin
@Bean
fun trailingSlashFilter() = UrlHandlerFilter.trailingSlashHandler("/**").wrapRequest().build()
```

## Testing

### Kiwi beans are missing in slice tests

A `@DataJpaTest` or `@WebMvcTest` fails to load the application context, because a Kiwi bean, like the `CommandBus`
or the `QuerySchemaService`, is missing:

```
NoSuchBeanDefinitionException: No qualifying bean of type 'de.kiwi.api.application.command.CommandBus' available
```

Slice tests disable `@EnableAutoConfiguration`, and only apply the auto-configurations relevant for the slice. The
Kiwi auto-configurations are not part of any slice. To resolve this, import the Kiwi auto-configurations your test
requires using `@ImportAutoConfiguration` on the test configuration, as in the access-control tests of the demo
applications (`demo/access-control-tests`):

```kotlin
@MustBeDocumented
@Target(AnnotationTarget.CLASS)
@Retention(AnnotationRetention.RUNTIME)
@DataJpaTest
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
@Import(AccessControlTestConfig::class)
annotation class AccessControlTest

@SpringBootConfiguration
@EntityScan("de.kiwi.demo.access")
@ComponentScan("de.kiwi.demo.access")
@EnableJpaRepositories("de.kiwi.demo.access")
@ImportAutoConfiguration(
    KiwiFrameworkAutoConfiguration::class,
    KiwiBusAutoConfiguration::class,
    KiwiMailAutoConfiguration::class,
    KiwiAuditLogPackagesAutoConfiguration::class,
    KiwiAuditLogAutoConfiguration::class,
)
class AccessControlTestConfig {
    // [...] Test beans
}
```

See [Chapter 7: "Testing and Frontend Code-Generation"](./07-testing.md).

## Jackson 3

### JsonNode.map transforms the node itself

After upgrading to Kiwi 1.5 (Jackson 3), code mapping the elements of a `JsonNode` array compiles, but behaves
differently:

```kotlin
// Jackson 2: maps each element of the array node
// Jackson 3: calls JsonNode.map(Function), which passes the array node itself to the lambda once
val names = node.map { it.asString() }
```

Jackson 3 added the member function `JsonNode.map(Function)`, which transforms the node itself. In Kotlin, a member
function takes priority over the `Iterable.map` extension function, so `node.map { }` silently changes its meaning.
To resolve this, iterate the elements explicitly:

```kotlin
val names = node.values().map { it.asString() }
```
